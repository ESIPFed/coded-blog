Read it live — by its CID

This runs today — no daemon, no credentials. Just pip install and open a 2 GB content-addressed ERA5 dataset over HTTP; Icechunk 2.0 verifies every byte against the hash.

In [1]:
import icechunk, xarray as xr CID = "bafybeicwoya7…avptj7y" # try the CODED gateway; fall back to ipfs.io GATEWAYS = ["http://44.239.118.35:8080", "https://ipfs.io"] for GATEWAY in GATEWAYS: try: st = icechunk.http_storage(f"{GATEWAY}/ipfs/{CID}") repo = icechunk.Repository.open(st) ds = xr.open_zarr(repo.readonly_session("main").store, chunks={}) print(f"✓ opened via {GATEWAY}"); break except Exception as e: print(f"✗ {GATEWAY} failed; trying next…")
✓ opened via http://44.239.118.35:8080

Preserve your dataset

Have a Zarr or Icechunk dataset you can’t afford to lose? Write it to Storacha (Filecoin-backed, free to 5 GB) and get a permanent CID anyone can verify — independent of any single institution.

1
Build / point at your Icechunk store
ds.to_zarr(icechunk_store)
2
Add to IPFS → content ID
ipfs add -r --cid-version=1 store/
3
Pin to Storacha/Filecoin
w3 up --car store.car
# one command with our coded-pin tool: coded-pin native my.zarr \ --name my-dataset \ --pin storacha \ --ipns my-dataset-current # → CID bafybei… (share it alongside your DOI)

The CID is a hash of the data — tamper-evident and location-independent. Add an IPNS name for a mutable pointer that follows every new version.

Why this matters

  • Content-addressed. The CID is the data’s fingerprint — verify you have exactly the right bytes, from anywhere.
  • Takedown-resistant. One budget cut or policy change can’t erase data that many nodes can pin and serve.
  • Zero adapter code. Icechunk’s http_storage reads a repo over any IPFS gateway — standard xarray/Zarr the whole way.
  • Reproducible. Every Icechunk commit is an immutable snapshot; an old CID always returns the old data.

Bottom Line

Reading distributed Earth data is a one-cell, no-credentials operation today — open any Icechunk/Zarr dataset by its CID, with automatic gateway fallback.

Preserving it is just as easy: one upload to Storacha mints a verifiable, Filecoin-backed CID. Publish it next to your DOI and your data outlives any single server.
